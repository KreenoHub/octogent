OCTOPLAN+OCTOGENT handbook · Octoplan v3

Plan it. Hand it off. Watch it get built.

You describe what you want. Claude asks you clear questions, one card at a time, and writes a plan. Then a team of Claude agents builds it, each working through its own to-do list. This handbook walks through every screen, from a brand-new idea (or a half-finished project) to agents writing code.

Before you begin

Start both apps

Octoplan, from the octogent repo:

pnpm install
pnpm --filter @octogent/octoplan dev

Then open http://127.0.0.1:5190. The server itself runs on port 8790.

Octogent you don't have to start yourself. Octoplan's Run Octogent button starts it in the right folder (step 7). By hand: go into your project and run octogent; its dashboard opens at http://127.0.0.1:8787, or the next free port.

Plan it · step 1

1 Start: a new idea, or something that exists

Octoplan opens on Home when you have no projects yet; the Home button, top left, brings you back any time. Your recent projects are listed underneath, including an import still waiting for review.

New project from an idea

  1. Describe the idea. A sentence or a paragraph is enough.
  2. Project name is suggested from your idea. Any language works; a Hebrew name makes a Hebrew folder name.
  3. Create it in defaults to where your latest project lives.
  4. Press Create and start planning.

Octoplan creates the folder (it refuses a folder that exists and isn't empty), sets up git with a first commit, writes a README.md with your idea and an empty docs/plan/, and starts a Deep interview. The first question arrives within seconds.

Import something that exists

For a repo, a folder of notes, half a plan, a spec you can paste, a chat log.

  1. Main folder: a repo or any folder. It becomes the project. Tip: in Windows Explorer, Shift+right-click → Copy as path; the quotes are removed for you.
  2. More files or folders, from anywhere. They're read, not copied.
  3. Pasted text. Each paste is saved as docs/plan/sources/pasted-1.md, pasted-2.md…
  4. Set up git (on by default): if the main folder has no git yet, Octoplan makes one empty commit. Your files are not committed.
  5. Press Import and read.

Claude reads plans and docs first (READMEs, .md, .txt, specs, PDFs), then manifests, and code only as needed. It never sees dependencies, build output, lockfiles or binaries. Word, PowerPoint, Excel files and images can't be read; they're listed as not read so you can paste their text. Big folders are capped at 400 listed files. The pass is read-only.

Plan it · step 2

2 Understand: check what Claude read

While Claude reads (usually under a minute) the step shows a spinner. You can leave and come back; the draft is saved.

First comes a maturity verdict for the whole import and for each source. It decides how the interview starts: a detailed plan gets fewer questions, a built project is asked "what's next?".

  • Raw ideaa sentence or a few lines
  • Notesscattered thoughts
  • Partial plansome decisions, big holes
  • Detailed planmostly settled
  • Builtworking code exists

Then the items Claude found, grouped into Goals, Non-goals, Decisions, Gaps and Risks. For each one you can keep it or untick to drop it, edit the title and details, and see its evidence: Found in file "exact quote", or Inferred: reason.

Items marked already in plan (D3) match something your plan has; they're shown and never written twice. Edits save automatically; Later closes the review. When ready, press Apply N items and start the interview: the kept items go into docs/plan/, and the interview asks only about what's still open. For a built project, the git history is also scanned for decisions. Importing again later shows only the new items.

Plan it · step 3

3 Interview: answer question cards

Claude asks rounds of question cards in the answer dock, which never scrolls away.

On a cardDoes
1–9 or clickPick an option. (Recommended) is Claude's suggestion
OType your own answer in Other…
TTentative: you're unsure (also recorded as a risk)
PPark it: decide later, with an assumption Claude can work with
EnterConfirm the round
Why this questionClaude's reasoning

The plan board on the right collects Goals, Decisions, Gaps, Parked items, Risks and Ideas, plus Coverage: twelve planning topics that go from empty to partial to covered. Needs attention lists anything waiting for you. Press F for Focus mode, just the question, big and centered. You can also type to Claude any time in the box under the conversation.

Plan it · step 4

4 Goal: the definition of done

When the topics are covered, the next-action bar offers Ask Claude to write GOAL.md. Claude writes the title, why, goals, non-goals and a definition of done where every item can be checked by running something. It may ask one or two last questions first.

Plan it · step 5

5 Stages: build prompts

Generate stages turns the goal and decisions into step-by-step build prompts, each self-contained and ending with a testing checkpoint. Copy prompt puts one on your clipboard for any Claude session.

Hand it off · step 6

6 Hand off to Octogent

The plan becomes Octogent tentacles (workstreams) with to-do lists, in four steps.

  1. Generate. Claude proposes 3–8 tentacles, each owning certain folders, with one-line to-dos that end in "Done when…" and cite their decision ([D12]).
  2. Review. Rename, add or remove tentacles, change their folders, edit, move or delete to-dos. Saved to docs/plan/HANDOFF.md.
  3. Apply. Creates the missing tentacles and writes their to-dos. Applying twice never duplicates, and your own notes are never touched.
  4. Done. Results, Open Octogent, and the octopus prompt with a Copy button (also docs/plan/OCTOPUS.md).

Octogent must be running in that folder for Apply to work. If it isn't, Octoplan says so and puts the fix right there: press Run Octogent, wait for Running :port, then Retry apply.

Advanced: "Export to one tentacle", under the wizard, writes chosen tasks into a single tentacle.

Build it · step 7

7 Build: Run Octogent

Run Octogent (in the Build step, the handoff, or the bottom bar) sets the folder up for Octogent if needed, opens a terminal window running octogent in your project, and waits for its real port. Then it shows Running :port and Open Octogent. If Octogent is already running, the button just opens it; it never starts a second copy. If no terminal can be opened, it shows the command with a Copy button.

First time in a folder: the first Claude terminal in Octogent asks whether to trust this folder. Accept it, or that terminal's first prompt is lost.

Build it · inside Octogent

Inside Octogent

Octogent's views are numbered; press 1–8 to switch. [2] Deck shows one card per tentacle with its to-do list and progress, and buttons: Spawn starts an agent, Vault holds its files.

[1] Agents shows the octopus in the middle and the tentacles around it. Click a tentacle for its panel: Create Agent starts one agent, Spawn Swarm starts several for a long list.

Start the work

  1. Open the octopus and paste the octopus prompt from Octoplan's Done step. It knows every tentacle, the order of the waves, and the rules: each agent stays in its own folders, and commits cite decision ids.
  2. The octopus spawns an agent per tentacle, or press Spawn / Create Agent yourself.
  3. Accept the folder-trust question the first time.
  4. Watch the to-dos tick off on the Deck, in Octoplan's Build step, and on the Tentacles n/m button in Octoplan's header.
Build it · afterwards

Closing the loop

Agents make decisions while they build. Octoplan catches them. Harvest reads new commits and to-do changes, automatically when you open the project or with Harvest now, and proposes decisions in Needs attention; rejected ones never come back. Drift badges show whether each decision is implemented, untouched or diverged. The board's History tab shows how the plan evolved.

Troubleshooting

You seeDo this
"The octogent CLI isn't on PATH"In the octogent repo: pnpm install && pnpm build && npm install -g ., then Run Octogent again
Apply says "Start Octogent in this repo first"Press Run Octogent, wait for Running, then Retry apply
"…process is alive, but :port isn't answering"Check the Octogent terminal window: it may still be starting, or show an error
An agent's first prompt did nothingIt was waiting on the trust question. Accept it and send the prompt again
The import takes a whileBig folders take a couple of minutes. Close the review and come back; it's saved
"Resolve or park … first"A Sources-disagree item is still open: choose Resolved or Parked, or untick it
A file shows as "Not read"It's a Word, PowerPoint or Excel file or an image. Paste its text into a new import
I can't find my importHome → Recent projects → the one marked "import waiting for review"
Octoplan says OfflineRun pnpm --filter @octogent/octoplan dev again; sessions come back
